# Proposal

## Why

Сейчас каждый EJS-остров инжектится как отдельный JavaScript-документ, поэтому конструкции со скобками, открывающимися в одном острове и закрывающимися в другом (`<% if (CLIENT) { -%>` ... `<% } -%>`), дают ложную ошибку «Missing }». Замер на реальном корпусе `application-template`: 66 из 364 островов (18%) несбалансированы по скобкам — то есть почти каждый пятый остров сейчас показывает фантомную ошибку.

## What Changes

- Инъекция JS переводится с «один инжект на остров» на **один инжект на файл**: все острова файла регистрируются как places одной JS-инъекции, поэтому скобки парсятся как единый код.
- Синтетический prelude (`h.*` + переменные контекста) ставится **один раз в начало** объединённого документа вместо повтора на каждом острове.
- Побочный выигрыш: объявления из одного острова (`const x = ...`) становятся видимыми в соседних островах того же файла — резолв, completion и references начинают работать между островами.
- **BREAKING** для внутренней архитектуры: `HygenEjsIslandInjector` (per-island) заменяется файловым инжектором; `HygenEjsPlaceholderInjector` переиспользуется для prelude на файловом уровне.
- Допущение: `ElementManipulator<HygenEjsIsland>` не требуется, если prelude вставляется через placeholder-helper на host-уровне; это проверяется первым шагом реализации (spike в реальной IDE).

## Capabilities

### New Capabilities

Нет — изменение поведения существующей возможности.

### Modified Capabilities

- `hygen-ejs-injection`: инъекция становится единым JS-документом на файл; добавляется требование кросс-островной связности (скобки, объявления).

## Impact

- `src/main/kotlin/com/biorate/hygen/lang/injection/HygenEjsIslandInjector.kt` — замена на файловый `MultiHostInjector` (или новый класс; старый удаляется).
- `HygenEjsPlaceholderInjector.kt` / `HygenEjsPrelude.kt` — prelude на уровне файла.
- `src/main/resources/META-INF/plugin.xml` — регистрация инжектора.
- Тесты инъекции/прелюда + корпусной прогон 187 шаблонов; версия 0.5.0.
