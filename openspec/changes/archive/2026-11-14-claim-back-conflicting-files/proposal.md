# Proposal

## Why

Ручная проверка 0.6.0 (`file-type-conflict-detector`) показала: путь «снять чужой паттерн» (tier 1) — не лучший выход. Пользователь dotenv-конфликта не захотел трогать паттерн `.env.*` чужого типа (он нужен для настоящих env-файлов) и решил конфликт вручную через UI Settings → Editor → File Types, добавив **точное имя** `.env.t` к типу Hygen Template — и это сработало: платформа резолвит точные имена файлов с приоритетом над glob-паттернами (документированное поведение `FileTypeManager`), dotenv сохраняет свои env-файлы, а `.env.t` возвращает нашему типу. При этом:
- ручная правка теряется для будущих конфликтов (новые конфликтные имена не появятся сами);
- детектор 0.6.0 продолжает репортить конфликт (он пробует синтетическое `.env.probe.t`, а не реальное имя, забранное точным);
- снятие чужого паттерна агрессивнее и ломается при обновлении чужого плагина (паттерн вернётся).

## What Changes

- **Claim-back как первый способ разрешения конфликта**: когда детектор находит пересечение «наш паттерн × чужой паттерн», notification предлагает **«Claim back»** — добавить конфликтные **точные имена файлов** (реально существующие в проекте, например `.env.t`) к нашему file type как exact fileName-ассоциации. Точное имя побеждает чужой glob — конфликт исчезает без правки чужих типов.
- **Только реальные файлы**: имена берутся из VFS (файлы, существующие в проекте и попавшие в пересечение), а не из генерации гипотетических имён — утверждаем только то, что реально есть.
- **Управляемые claim'ы**: плагин помнит, какие exact-имена он добавил (persistent state), и на каждом sync-цикле **снимает** те из них, чьё пересечение с настройками исчезло (например, пользователь убрал `*.t`) — claim'ы не накапливаются как мусор.
- **Resolve (снятие чужого паттерна) остаётся** вторым вариантом в диалоге разрешения — на случай, если пользователь предпочитает убрать чужой паттерн целиком.
- **Детекция учитывает claim'ы**: имена, уже забранные точным именем и резолвящиеся в наш тип, больше не репортятся как конфликт.
- Допущения (из эксплорации): точное имя бьёт чужой glob — подтверждено пользователем эмпирически в IDEA 2025.2; приоритет среди **конкурирующих exact-имён** недокументирован — закрывается спайк-задачей; claim добавляется только после явного подтверждения (никаких silent-правок нашего типа тоже).

## Capabilities

### New Capabilities

- `hygen-file-type-claims`: claim-back конфликтных файлов точными именами с управляемым жизненным циклом claim'ов.

### Modified Capabilities

- `hygen-file-type-conflicts`: уведомление предлагает claim-back как предпочтительное действие; детекция не репортит файлы, уже резолвящиеся в наш тип через exact-имя.

## Impact

- Расширение пакета `conflicts/`: claim-менеджер (добавление/снятие exact-имен), persistent state claim'ов, обновление контроллера/репортера (новое действие в balloon).
- VFS-обход для поиска реальных файлов под пересечением (ограниченно: корни контента проекта, фильтр по имени).
- Диалог выбора: список конфликтных файлов → «Claim back selected» / «Remove foreign pattern» / «Suppress».
