# Proposal

## Why

Движок `@biorate/hygen` поддерживает четыре имени конфиг-файла (`.hygen.js/.cjs/.mjs/.ts`) и валидирует значения `setup:`/`from:` на рантайме (`SetupRepositoryError`, падение чтения файла). Плагин покрывает только `.hygen.js` и не проверяет эти значения статически — проекты с TS-конфигом не получают контекст-переменных, а ошибки в `setup:`/`from:` всплывают только при запуске генератора.

## What Changes

- `HygenConfigLocator`: поиск ближайшего конфига по всем четырём именам движка с его порядком разрешения (ближайший каталог вверх; внутри каталога приоритет `.hygen.js → .hygen.cjs → .hygen.mjs → .hygen.ts`).
- Новая инспекция: `setup:` без `/` в значении — warning «движок выбросит SetupRepositoryError».
- Новая инспекция: `from:` указывает на несуществующий файл относительно ближайшего вверх `_templates`-каталога — warning; при отсутствии каталога инспекция молчит (никаких ложных срабатываний).
- Engine-дефолты контекста: спец-переменные `ts` (timestamp запуска) и `_` (позиционные аргументы CLI) становятся видимыми в completion — движок прокидывает их в шаблоны (коммиты `c2d99984b`/`53382a948`).
- Допущения (обсуждены, пользователь не возражал): templates-каталог ищется walk-up от файла шаблона; TS-конфиг читается тем же JS-PSI парсером.

## Capabilities

### New Capabilities

- `hygen-config-resolution`: обнаружение и чтение конфиг-файла проекта (четыре имени, порядок разрешения движка) как основа контекста шаблонов.

### Modified Capabilities

- `hygen-validation`: добавляются требования статической валидации значений `setup:` и `from:`.

## Impact

- `src/main/kotlin/com/biorate/hygen/context/HygenConfigLocator.kt` + его тесты (порядок разрешения).
- `src/main/kotlin/com/biorate/hygen/context/HygenTemplateContext.kt` (использует локатор — только через его API, без правок семантики).
- Новые файлы в `inspection/` (2 инспекции) + регистрация в `plugin.xml`.
- Версия 0.4.0 в `build.gradle.kts`.
