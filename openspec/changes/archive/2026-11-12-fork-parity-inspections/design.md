# Design

## Context

`HygenConfigLocator` — чистый объект с константой `CONFIG_FILE_NAME = ".hygen.js"` и walk-up `findNearestConfig`; его использует `HygenTemplateContext` (кэш по пути + `JavaScriptConfigParser` над JS PSI). Шесть существующих инспекций дают готовый паттерн (frontmatter-ключ + значение через PSI). Движок: `config-resolver.ts` (двухуровневый порядок: каталог вверх, внутри — порядок имён), `ops/setup.ts` (`SetupRepositoryError` без `/`), `ops/add.ts` (`from` → `templates/<from>`).

## Goals / Non-Goals

**Goals:**
- Паритет с движком по обнаружению конфига (4 имени, его порядок).
- Раннее статическое выявление ошибок `setup:`/`from:`.

**Non-Goals:**
- Mirror-семантика (inlay цели) — отдельный чейндж.
- Dry-run, каталоги из `.d.ts`, YAML layering — backlog §8.
- Переопределение templates-каталога (`HYGEN_TMPLS`) — не трогаем.

## Decisions

1. **Порядок разрешения — точная копия движка:** для каждого каталога вверх проверяем имена в порядке `.js → .cjs → .mjs → .ts`. Альтернатива («первый существующий из всех имён по всему дереву») неверна — в одном каталоге движок отдаёт приоритет `.js`, даже если `.ts` лежит «ближе по списку». Тестируем на temp-каталогах (чистый `java.io.File`).
2. **`.hygen.ts` читается тем же `JavaScriptConfigParser`** — TS-файл парсится JS PSI платформы; ts-node движка нас не касается (мы не исполняем конфиг). Риск: TS-специфичный синтаксис (satisfies, generics) в `localsDefaults`/`helpers` — парсер молча вернёт пусто, что допустимо (graceful degradation, как сейчас для непарсируемого `.js`).
3. **Templates dir для `from:`** — walk-up от файла шаблона до первого `_templates`; не нашли — инспекция молчит. Альтернативы (content root модуля, `.hygen.js`-рядом) отброшены: движок резолвит от CLI-cwd, которого в IDE нет; `_templates`-по-имени — надёжный прокси и покрывает монорепо.
4. **Инспекции — отдельные классы**, обе warning-severity, без quick-fix (движок поведёт к ошибке рантайма; фикс контекстно-зависим). Регистрация в `plugin.xml` по существующему паттерну `localInspection`.
5. **Совместимость:** `findNearestConfig` сохраняет сигнатуру; `HygenTemplateContext` меняется только внутри (список кандидатов вместо одного имени).

## Risks / Trade-offs

- Небольшой рост ФС-опроса при открытии шаблона (до 4 проверок на каталог вместо 1) — пренебрежимо; кэш в `HygenTemplateContext` остаётся.
- Инспекция `from:` может молчать там, где движок бы упал (нестандартное имя templates-каталога) — осознанный trade-off против ложных срабатываний.
