# Hygen Template Support

[English documentation → README.md](README.md)

Плагин для IntelliJ IDEA: поддержка шаблонов генератора кода **@biorate/hygen** — подсветка синтаксиса, структурная валидация, автодополнение и языковые инъекции для файлов шаблонов (`.t`).

## Что делает плагин

- **Распознавание шаблонов** — выделенный тип файла для шаблонов hygen. Набор шаблонов имён файлов настраивается (по умолчанию `*.t`, доступны также пресеты `*.ejs.t`, `*.tmpl` и собственные маски); изменения применяются без перезапуска IDE.
- **Подсветка синтаксиса** — YAML frontmatter (блок `--- … ---`) и EJS-теги в теле шаблона, с настраиваемыми цветами (страница настроек цветов + схема для предпросмотра).
- **Инъекция языка-хозяина** — тело шаблона получает подсветку и анализ целевого языка (JS/TS и т.д.), определяемого по расширению в значении `to:` frontmatter (в т.ч. когда путь содержит EJS-интерполяции).
- **Инъекция JavaScript в EJS-«острова»** — код внутри `<% … %>`, `<%= … %>` и их trim-вариантов получает полноценную поддержку JS: подсветку, анализ ошибок и автодополнение. Ссылки в инъецированном коде разрешаются синтетическими объявлениями (без ложных «unknown symbol»): `h`, переменные контекста шаблона, helpers из конфига проекта (`.hygen.js`/`.hygen.cjs`/`.hygen.mjs`/`.hygen.ts`). Все EJS-«острова» шаблона анализируются как единый JavaScript-документ, поэтому скобки или объявления, охватывающие несколько островов, больше не дают ложных ошибок (а объявления из ранних островов видны в последующих).
- **Инспекции (уровень 1, структурные)**:
  - *Unknown frontmatter key* (warning) — неизвестный ключ frontmatter (набор ключей форка `@biorate/hygen`: `to`, `inject`, `sh`, `before`, `after`, `prepend`, `append`, `at_line`, `skip_if`, `skip_if_not`, `create_if_missing`, `replace`, `unless_exists`, `local`, `setup`, `force`, `message`, `echo`, `spinner`, `sh_ignore_exit`, `mode`, `verbose`, `from`, `eof_last`, `mirror`);
  - *Unterminated frontmatter block* / *Unterminated EJS tag* (error) — незакрытый блок frontmatter или EJS-тег;
  - *Mutually exclusive inject and replace* (error) — одновременное использование `inject` и `replace`;
  - *Anchor option without inject mode* (warning) — якорные опции (`before`, `after`, `prepend`, `append`, `at_line`) без режима `inject`;
  - *EJS tags in hook file* (warning) — EJS-теги в hook-файлах (`prompt.js`/`index.js`/`prompt.ts`/`index.ts`), где они движком не обрабатываются;
  - *Setup value without owner/repo* (warning) — значение `setup:` без вида `owner/repo`, который ждёт движок (он выбросит `SetupRepositoryError`);
  - *From file not found* (warning) — значение `from:` указывает на несуществующий файл относительно ближайшего `_templates` (молчит, если `_templates` не найден).
- **Автодополнение** — ключи frontmatter с описаниями семантики форка; члены объекта `h` (`h.changeCase.*` — 40 методов, `h.inflection.*` — 16 методов, а также `h.capitalize`, `h.path` и др.); переменные контекста шаблона, включая движковые спец-переменные `ts` (timestamp запуска) и `_` (позиционные аргументы CLI).
- **Контекст шаблона** — плагин понимает, какие переменные доступны в шаблоне: движковые дефолты (`name`, `Name`, `names`, `Names`, а также спец-переменные `ts` и `_`), `localsDefaults` из конфига проекта, переменные из prompt-хуков, а также переменные, объявленные в самом шаблоне.

## Требования

- IntelliJ IDEA **2024.3+** (`since-build 243`).
  - Базовые функции (подсветка, инспекции, frontmatter-дополнение) работают в **Community Edition**.
  - Инъекция JavaScript/TypeScript (в тело шаблона и в EJS-острова) требует **IDEA Ultimate** — она опирается на плагин JavaScript.
- Плагин собирается из исходников: **в Marketplace он пока не опубликован**.

## Установка

1. Соберите плагин:
   ```bash
   ./gradlew buildPlugin
   ```
2. Артефакт появится в `build/distributions/idea-hygen-plugin-<версия>.zip` (текущая версия — `0.7.0`).
3. В IDE: **Settings → Plugins → ⚙ → Install Plugin from Disk…** и выберите zip.
   Альтернатива: распаковать zip и скопировать каталог плагина в папку плагинов IDE (`~/.local/share/JetBrains/IntelliJIdea<versia>/plugins` и т.п.).
4. Перезапустите IDE.

## Настройка

**Settings → Tools → Hygen Templates**:

- Редактируемый список масок имён файлов для шаблонов hygen, с пресетами:
  - `*.t` (по умолчанию),
  - `*.ejs.t`,
  - `*.tmpl`,
  - плюс любые собственные маски. Есть валидация ввода; изменения применяются сразу, без перезапуска IDE.
- Файлы внутри `_templates/**` (внутри папки action-а) считаются шаблонами **все**, кроме `prompt.js` / `index.js` / `prompt.ts` / `index.ts` — они остаются обычными JS/TS-файлами (hook-файлы). Это соответствует поведению самого движка.
- ⚠️ Обратите внимание: маска по умолчанию `*.t` захватывает расширение `.t` во всей IDE — если у вас есть другие `.t`-файлы, сузьте список масок.
- **Конфликтующие типы файлов** — если другой тип файла захватывает те же маски имён, что и маски ваших hygen-шаблонов (например, встроенный плагин *Env files* с маской `.env.*`, затеняющий маску шаблона `.env.t`), плагин обнаруживает это и предлагает **вернуть ваши реальные файлы**: он находит существующие файлы проекта, попавшие в пересечение маски hygen-шаблона и маски чужого типа файла, и предлагает добавить их **точные имена** в тип hygen-шаблонов. Точные имена имеют приоритет над glob-масками чужого типа, поэтому ваши файлы снова разрешаются в hygen, при этом маски чужого типа файлов остаются нетронутыми. «Удалить чужую маску» (удаление только конфликтующей маски из другого типа после явного подтверждения) остаётся доступной альтернативой. Заявки сохраняются между перезапусками и автоматически снимаются, когда маска hygen удаляется или заявленный файл исчезает. Тот же конфликт всегда можно разрешить вручную: **Settings → Editor → File Types → \<конфликтующий тип\> → File name patterns**.

## Краткая справка по синтаксису шаблонов

**Frontmatter** — YAML-блок в начале файла:

```yaml
---
to: app/emails/<%= name %>.ts
inject: true
after: // add-email-here
---
```

Основные ключи: `to`, `inject`, `sh`, `before`, `after`, `prepend`, `append`, `at_line`, `skip_if`, `skip_if_not`, `create_if_missing`, `replace`, `local` и др. Полный список ключей и их семантика — в документации движка (ссылки ниже).

**EJS-теги** в теле шаблона:

| Тег | Назначение |
|---|---|
| `<%= выражение %>` | интерполяция с экранированием |
| `<%- выражение %>` | интерполяция без экранирования |
| `<% код %>` | скриптлет (исполняемый JS) |
| `<%# комментарий %>` | комментарий |
| `<%-`, `-%>`, `<%_`, `_%>` | маркеры обрезки пробелов/переводов строк |
| `<%%` | экранирование литерального `<%` |

**Хелперы `h`** — доступны внутри EJS-тегов: `h.changeCase.*` (пакет [change-case](https://www.npmjs.com/package/change-case), 40 методов), `h.inflection.*` (пакет [inflection](https://www.npmjs.com/package/inflection), 16 методов), `h.capitalize`, `h.path` и др.

**Переменные контекста**: `name`, `Name`, `names`, `Names` (дефолты движка, всегда доступны), движковые спец-переменные `ts` (timestamp запуска) и `_` (позиционные аргументы CLI), переменные из `localsDefaults` в конфиге проекта (`.hygen.js`/`.hygen.cjs`/`.hygen.mjs`/`.hygen.ts`), переменные, запрошенные в prompt-хуке (`prompt.js`), и переменные, объявленные в самом шаблоне.

## Разработка

```bash
./gradlew test        # тесты (JUnit + платформенный тестовый фреймворк)
./gradlew buildPlugin # сборка дистрибутива
./gradlew runIde      # запуск IDE-песочницы с плагином
```

Проект развивается по OpenSpec-процессу: спецификации возможностей лежат в `openspec/specs/` (язык шаблонов, валидация, определение языка-хозяина, резолвинг конфигурации, инъекция EJS, автодополнение, контекст шаблона), итоги ручной и автоматической проверки — в `VERIFICATION.md`.
